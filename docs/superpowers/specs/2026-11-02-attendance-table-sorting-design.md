# Сортировка таблицы на странице «Посещаемость» — дизайн

Дата: 2026-11-02

## Intent

На странице «Посещаемость» (`ui/src/routes/_logged-in/$yearId/attendance.tsx`) менеджер видит таблицу: строки — волонтёры (сейчас сгруппированы по должностям), колонки — должность, зал, имя и по одной колонке на каждый день. Нужно, чтобы таблицу можно было сортировать по любому столбцу кликом по его заголовку. Это помогает быстро находить человека и видеть паттерны посещаемости.

## Goals

- Клик по заголовку столбца переключает сортировку asc → desc → выкл (как на странице «Контакты»).
- Сортируемые столбцы: Должность, Зал, Имя и каждая колонка дня (по статусу посещаемости).
- Сортировка глобальная по всей таблице; название должности показывается в каждой строке (решено с партнёром — группировка «одно название на группу» при глобальной сортировке ломается).
- Сортировка только на клиенте: данные уже приходят одним запросом (`useAttendance`), бэкенд и API не меняются.

## Non-goals

- Серверная сортировка, пагинация, изменения API.
- Сортировка по оценкам (assessments) внутри ячеек дней.
- Сохранение состояния сортировки в URL — при уходе со страницы сбрасывается.
- Кнопка «сбросить сортировку» (цикл asc/desc/выкл и так её сбрасывает).

## Anti-goals

- Сломать существующее поведение: клик по статусу в ячейке дня меняет посещаемость, `AssessmentInput` в ячейке работает как раньше, вкладки дней и селектор посещаемости не меняются.
- Визуальные регрессии (sticky header, размеры, скролл).

## Constraints

- Паттерн — TanStack Table (`@tanstack/react-table` уже в зависимостях), как на страницах `contacts.tsx` и `users/index.tsx`: `useReactTable`, `getSortedRowModel`, кликабельный заголовок со стрелкой направления.
- MUI-компоненты, идём в существующий стиль страницы.
- Новых пользовательских строк нет (заголовки уже переведены) — переводы не нужны.

## Approaches

1. **Сортировка внутри групп должностей** — структура таблицы не меняется, сортировка применяется только внутри каждой должности. Отклонено: партнёр выбрал глобальную сортировку — так удобнее искать человека по имени среди всех должностей.
2. **Глобальная сортировка на TanStack Table** (выбрано) — строки плоским списком, должность в каждой строке, сортировка по любой колонке. Ложится на существующий паттерн проекта, не требует новых зависимостей.
3. Вручную на `useState` + `Array.prototype.sort` — отклонено: изобретает то, что уже стандартизировано в проекте через TanStack Table.

## Решения, принятые в разговоре

- Глобальная сортировка по всей таблице, должность отображается в каждой строке.
- Сортируемы все колонки, включая дни.

## Calls, сделанные мной (проверить при чтении)

- Порядок рангов статуса посещаемости для сортировки колонок дней: `yes` → `late` → `sick` → `no` → `unknown` → нет записи; переключение asc/desc даёт обратный порядок.
- Сортировка по умолчанию не задана (исходный порядок от бэкенда), как на страницах контактов/пользователей.
- Стрелка направления и цикл asc/desc/выкл — как в `contacts.tsx`.

## Что оставляю исполнителю

- Преобразовать данные в плоский массив строк (тип `VolunteerAttendance` уже есть; уникальность строки — пара `user_id` + `position_id`).
- Колонки: `position_name`, `hall_name`, `user_name` (accessor из полей строки) + динамические колонки дней (accessor — статус посещаемости пользователя в этот день, с рангом выше; дни вне записи — в конец при asc).
- Рендер заголовков по образцу `contacts.tsx` (клик, курсор, стрелка `↑`/`↓`), рендер ячеек дней — существующий JSX без изменений поведения.
- Убрать проп `isFirstInPosition` и логику группировки в рендере (данные больше не рендерятся группами); порядок строк теперь определяет `table.getRowModel()`.

## Проверка

- `pnpm test`, `pnpm typecheck`, `pnpm check` (biome) в `ui/` — зелёные.
- Ручная проверка: dev-сервер, страница «Посещаемость» — клики по заголовкам сортируют (должность/зал/имя/день), переключение вкладок дней работает, сортировка корректна при фильтре «один день», клик по статусу в ячейке по-прежнему сохраняет посещаемость.
